## Font/outline source boundary

Read-only inspection used pinned SDK 0.5.1 and the same G layout WASM, SHA-256
`918f167735595e15440c25722f399babba6ecc605d30abbbc151c982404e0478`.
The layout WASM and its patch metadata have no differences between G and the
local source used for the isolated Node probe. Shared dependencies stayed
read-only, and no native app/converter or local GUI was launched.

The SDK's `GlyphCache.build` can represent a valid empty outline as a null path.
However, an unregistered FontId is not silently treated as an empty outline by
the actual WASM: a fresh isolated instance returned `unknown FontId for this
FontStore` for FontIds 0, 1 and 999 at glyph 36. Source inspection of the SDK's
glyph renderer shows a thrown provider error reaches its existing `fillText`
fallback. Thus the specific assumption “an empty main-thread font store simply
returns and permanently caches empty outlines” is not supported by this probe.
This does not observe native font IDs, prove a working fallback on WKWebView,
or eliminate other font/frame/readiness faults.
