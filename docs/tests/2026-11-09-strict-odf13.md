# Strict ODF 1.3 conversion profile (#31)

## Confirmed defect and repair

With the original conversion profile, LibreOffice 26.8.2.2 exports D1 as ODF
1.4. Its content, styles, metadata, settings and manifest fail the official
ODF 1.3 schemas. This does not meet #31's explicit ODF 1.3 requirement.

Set `/org.openoffice.Office.Common/Save/ODF/DefaultVersion` to `10`, the
[upstream strict 1.3 enum value](https://github.com/LibreOffice/core/blob/master/include/unotools/saveopt.hxx).
The item must precede the existing Common/Security items in this profile:
placing the same setting at the end was independently observed to be ignored
by this converter. Two failed probes (including a finalized/typed variation)
and the successful preceding-item probe are retained under
`.local/writer-conversion/strict-13*`.

Only that profile setting changes conversion behavior. The existing macro,
external-link and recovery settings remain intact.

## Independent schema verification

`scripts/test-odf-13.py` creates a separate macro-disabled profile for each
conversion, uses the production filter names, retains the original 45-second
process limit, and validates the resulting package with lxml. On timeout it
stops its own process tree. Source fixtures are never overwritten.

The script downloads the official OASIS schemas, requires their recorded
SHA256 hashes, and validates content.xml, styles.xml, meta.xml, settings.xml
and META-INF/manifest.xml. It also checks the format-specific mimetype, that
the mimetype entry comes first and is stored without compression, and that
each XML root declares version 1.3.

All **30 checks passed** on the fixed profile:

| Source | Output | Checks | Conversion time |
| --- | --- | ---: | ---: |
| D1.docx | ODT | 6/6 | 17,797 ms |
| D2.docx | ODT | 6/6 | 15,610 ms |
| D3.docx | ODT | 6/6 | 21,844 ms |
| Empty XLSX template | ODS | 6/6 | 24,079 ms |
| Empty PPTX template | ODP | 6/6 | 21,328 ms |

These are measured Windows conversion times, not performance guarantees.
The complete profile/schema/input/output hashes and individual checks are in
`2026-11-09-strict-odf13.json`. Original outputs and profiles are retained under
`.local/odf-13`. The schema sources are
[the OASIS document schema](https://docs.oasis-open.org/office/OpenDocument/v1.3/os/schemas/OpenDocument-v1.3-schema.rng)
and [manifest schema](https://docs.oasis-open.org/office/OpenDocument/v1.3/os/schemas/OpenDocument-v1.3-manifest-schema.rng).

The added GitHub Actions job installs the converter and pinned validator,
runs these five export/schema cases and uploads schemas, profiles, output
files and the JSON report. This workflow has been syntax-checked with
Prettier but has not yet run on GitHub.

## Additional Writer round trips and limitations

The earlier real-converter matrix passed all three generated legacy DOC
cases, D1–D3, both without editing and after the prescribed edit, save and
reopen. An independent Python XML reader compared the returned text and
features, and the actual Yrs engine reopened the outputs. The ODT D2 case
also passed this round trip. These are fixtures generated from the project's
synthetic DOCX corpus, not evidence for all historical Word/ODF producers.

Two earlier ODT cases timed out at the unchanged 45-second limit. A later
full-access Windows repetition of the three ODT round trips also timed out;
the harness stopped its own process trees and no such test processes remained.
The reason is not established. Those failures remain recorded in
`.local/writer-conversion*/vitest.json`; they are not treated as successful
round-trip acceptance or resolved by the five schema successes above.

Keep #31 open. The profile/schema repair does not establish complete content
or visual preservation, reliable completion of every round trip, installed
desktop-app acceptance, or broad legacy-format coverage. The native app was
not rebuilt in this follow-up. #2 and #34 also retain their remaining scope.
