# Separate Windows Presentation direct-canvas input

The user requested the remaining direct canvas route after the six bounded
standalone cores and short #377 were delivered at844bb1aa. Integration confirmed
this chat as the sole Windows canvas QA owner. No other platform/product owner
is implied, and the accepted ordinary Outline core is preserved unchanged.

The earlier failed driver waited for a contenteditable, input or textarea after
double-clicking the actual source-title hitpoint. P5 explicitly uses
`PptxEditor legacySyncApi` in `src/editors.tsx`. The installed SDK0.5.1 legacy
chunk `chunk-MCMFIO5A.js` (SHA256
`e3c0950a4c3b1f03dcf8b67fa0cff523c24ce8722812251c97788e842fcbb85d`)
instead focuses a DIV with role=application and tabindex=0. Its keydown handler
handles text insertion and Ctrl+End. The newer worker editor's hidden textarea
is a different route. Initial exploratory reading of the old base-checkout
SDK0.2.0 was not treated as the final contract; the same contract was then
verified in actual installed0.5.1, matching the P5 dependency version/lock pin.

This establishes a driver predicate mismatch, not a native canvas pass or a
product input bug. Open and closed canvas/presentation/text issue descriptions
were checked; no new product issue is registered without native reproduction.

The separate `presentation-canvas` case keeps original P5 source/tree/version,
producer/job/attempt, original child ZIP/receipt/report/NSIS/PE/signatures and
private runtime/profile gates. It uses an owned fresh hosted Windows VM only.
Before keys it records actual activeElement and OS focus, requires the unique
connected visible SDK stage enclosing the real canvas to own focus, and uses
the unchanged source XML's title hitpoint. It then types real keys, observes
ordinary Outline values without modifying them, renders the slide, saves PPTX,
fully exits, starts a different PID, reads the content again and saves again.
Independent XML and actual screenshots remain required. All guard failures
retain focus observations. No SDK/model setter, injected focus or driver
mutation of product DOM/state is used.

Only one directed Presentation child case is scheduled; the artifact is named
`standalone-windows-p5-presentation-canvas-proof`. The collector retains every
existing source/identity/native/byte/cleanup requirement and additionally checks
both phase focus probes and no-Outline-mutation readbacks. Existing accepted
core evidence and original failed runs are not overwritten. No canonical parent
download, application build, release intake, main/tag or publication.
