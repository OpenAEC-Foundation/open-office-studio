# Legacy Word corpus and DOC object warning (#2, #34)

## Confirmed deviation and repair

The pinned Apache POI `word_with_embeded.doc` contains four embedded objects.
The real converter imports them as two XLSX packages, a PPTX package and a
DOCX package, alongside four preview images. Both no-op and edited saves
through the production Yrs engine preserve all eight parts byte for byte.

Exporting the edited document back to DOC and importing that exact result
produces only three embedded packages: the PPTX payload disappears while its
preview remains. The document's paragraph text is retained. The independent
ZIP inspection confirms loss of an editable object, rather than only a
change from VML to DrawingML or an image filename change. The other three
embedded packages are rewritten by the converter; byte identity is not
claimed for the DOC round trip.

Before this patch, the actual `verliesrapport` function only returned the
generic older-format warning for this document. Add the embedded-object
category to the measured loss warning specifically for Writer DOC exports.
The existing localized loss explanation and DOCX suggestion are reused.
DOCX saves and ODT exports do not inherit this DOC-specific finding. The user
can keep the editable objects by saving the tested document as DOCX.

Four new tests call `verliesrapport` with a real package-name preflight:
one reproduces the missing DOC warning on the original module; three control
cases already pass. All four pass with the patch, as do the existing sixteen
report tests. The integrated local suite passes **2,004 tests, ten existing
skips**, across 178 files. TypeScript and the production build pass. No
translation keys, macro policy or converter settings change in this patch.
